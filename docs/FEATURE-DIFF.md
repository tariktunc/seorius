# Seorius — feature diff: SEO META in 1 CLICK v2.67 vs SEOquake v4.3.0

Written 2026-10-28 from a code-level read of both installed extensions. Clean-room: this document
describes behaviour in our own words. No code from either extension is reproduced; a few one-line
regex or constant values are quoted only as evidence of a threshold.

## How to read this

**Evidence tags** (file names are relative to each extension folder):

| Tag | File | Role |
|---|---|---|
| 1C-cs | `content_script.js` (1 CLICK) | all page extraction and rendering, jQuery |
| 1C-pop | `popup.js` (1 CLICK) | injects 1C-cs, shows tabs |
| 1C-bg | `bg.js` (1 CLICK) | dead analytics stub, no logic |
| SQ-cnt | `content-scripts/content.js` | SEOquake page extractor (answers one message, `page:getData`) |
| SQ-aud | `chunks/semrush-*.js` | SEOquake audit rules, thresholds, link-status policy, image rows |
| SQ-bg | `background.js` | webRequest capture, robots.txt / sitemap / link probes, request guard |
| SQ-rep | `chunks/report-*.js` | report UI, CSV writers, compare form |
| SQ-pdf | `chunks/exportAuditPdf-*.js` | PDF writer (a React PDF renderer) |
| SQ-set | `chunks/settings-*.js` | settings screens |
| SQ-bar | `content-scripts/seobar.js` | always-on bar, location-change watcher |
| ENG | `webforge/site-builder/seo-uzman/health/page-inspect-core.mjs` + `_config/on-page-rules.json` | our engine |

**"Present"** means code implementing the behaviour was found, not just a UI label.
**"Absent"** means searched and not found. **"Not determined"** is listed at the end with the reason.
Statements marked *(inferred)* come from reading selectors or regexes, not from running the extension.

**Engine column:** yes = covered the way Seorius needs; partial = covered with a gap named in the row;
no = not in `page-inspect-core.mjs` (a sibling tool in `seo-uzman/` may exist and is named).

**Architectural facts that shape many rows**

- 1 CLICK is pure DOM reading: permissions are `activeTab` and `scripting` only. It cannot see
  response headers, status codes or cross-origin resources, and it keeps no settings.
- SEOquake needs `<all_urls>`, `tabs`, `webRequest` and `storage`. That is how it gets status, redirect
  chain, HSTS and `X-Robots-Tag`. It sends URLs to Semrush by default (Seorius excludes this).
- SEOquake's extractor runs in the **top frame only** (no `all_frames` in its manifest). 1 CLICK injects
  into **all frames**.
